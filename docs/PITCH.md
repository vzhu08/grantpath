# Pitch scripts

## Two minutes

0:00–0:20: One user's concrete problem and evidence. “When [user] needs [outcome], today they [friction].”
0:20–1:15: Show the core workflow with the actual demo input. Let the result be visible; avoid narrating setup.
1:15–1:40: Explain the distinctive implementation and one measured comparison. Separate kit reuse, original event work and configured provider work.
1:40–2:00: State user value, a known limitation and the next validation step. End on the useful result.

## Three minutes

0:00–0:30: Problem/user/evidence. 0:30–1:45: Live core workflow plus source/review or failure behavior. 1:45–2:20: Architecture and technical differentiator. 2:20–2:45: Evaluation, latency/cost assumptions and limits. 2:45–3:00: Next step and result.

Replace timings with rehearsal measurements. Never call fixture output live or state unmeasured performance as fact. Sponsor mentions should correspond to actual verified use.
