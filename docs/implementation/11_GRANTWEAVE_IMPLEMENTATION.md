## 1. Decision, value and authorized scope

GrantWeave answers: **Can these three to five selected funding sources support this fixed, researcher-confirmed work plan under these confirmed conditions, and what binds?** It assigns each new dated cost exactly once, checks coupled financial/time/resource restrictions, and retains a source-linked explanation and assumptions. It does not add opportunity maxima and call them money available.

The concrete researcher problem is a plan that appears affordable in aggregate but cannot be funded because the money arrives in the wrong periods, excludes a necessary cost, repeats existing support, or requires unavailable effort. The distinctive mechanism is the connection from an exact assignment or impossibility proof to immutable source interpretations, work identities and funding branches. This is a project differentiator to demonstrate, not a claim of market uniqueness.

Judge-visible proof: a $12,000 synthetic plan is conditionally feasible with one $7,000 secured source and a hypothetical $5,000 award. A $16,000 aggregate branch becomes infeasible under an explicit scoped overlap rule; a separately retained counterfactual removing that invented rule restores the exact witness. Other planted cases reject incompatible dates, duplicate cost allocation and excess personnel effort. Funding success, scientific validity and institutional permission are not outputs.

Standing context: [project brief](../PROJECT_BRIEF.md), [roadmap11](../ROADMAP.md#11--grantweave-compatible-funding-combinations). ## 7. Constraint model and exact bounded search

Let `i` identify a new cost item, `f` a source, `p` a person, `t` a month, `r` a resource, and `x[i,f]` be0/1. Constants are confirmed exact amounts/units. The solver does pure feasibility and a few deterministic witnesses; no funding-probability or scientific-merit objective.

| Constraint | Formal meaning / trace |
| --- | --- |
| Cost conservation | For every required item, `sum_f x[i,f] = 1`; stable economic identities unique and disjoint from already covered support. Rejected duplicates are invalid inputs/witnesses, not extra funds. |
| Eligibility | `x[i,f]=0` unless source is usable in the branch, category/package/scoped activity is explicitly eligible, cost incurred date is within its reviewed budget window, and relevant activity is within reviewed performance dates. Unknown eligibility blocks conclusion. |
| Total/category/period caps | `sum_i amount[i]*x[i,f] <= capacity[f]`; equivalent sums on each confirmed category/period subset. Each rule pins its applicable source/version/scope. No independent maxima are promoted into available money. |
| Effort | For every person/month, `outside[p,t] + sum_requiredWP effort[wp,p,t] <= capacity[p,t]`. This includes unpaid effort and does not depend on `x`. Salary eligibility/compensation rules, if later introduced, are separate constraints. |
| Resources | For every resource/month, existing reservations plus required package demand must fit confirmed capacity in the same units. Monthly aggregation assumes no within-month conflict; finer scheduling is outside this demo. |
| Dependencies | Required predecessor exists, dependency graph acyclic, and predecessor end strictly before successor start for the chosen finish-before-start predicate. Missing/cyclic graph is invalid; fixed dates violating a valid dependency make the modeled plan infeasible. No automatic rescheduling. |
| Mutual exclusion | For an explicit scoped support restriction, let `y[f,scope]` be the logical OR of confirmed existing in-scope support (including paid/committed/external support within the rule's applicable stage/interval) and any new assigned in-scope cost. Enforce `y[A,scope]+y[B,scope] <=1`. Zero new allocation or zero remaining capacity does not erase existing support. Unknown existing scoped support blocks the conclusion. A coholding restriction instead uses award-presence status; do not silently substitute the support predicate. |
| Specific cost conflicts | A confirmed disallowed source/cost pair or incompatible support pair removes that assignment/combination even when categories fit. This is separate from scientific overlap. Labels cannot change either identity or scope. |

**Method choice:** TypeScript finite-domain DFS/backtracking with exact integers; no new solver package for this bounded release. Precheck input completeness, funding-independent effort/resources/dependencies and simple necessary capacity bounds. Compile an eligible domain per cost from confirmed rules; sort items by domain size then stable ASCII ID, sources by stable ASCII ID. Enumerate one source per item, prune only proven violations or sound upper bounds on remaining capacity, and independently recheck every complete witness against the unpruned original input.

Use a versioned deterministic node definition: one recursive partial assignment entered, including root; count before evaluation and stop before exceeding the budget. Proposed50,000 nodes per branch/200,000 per comparison, retain up to3 witnesses in traversal order. These are initial engineering bounds requiring measured acceptance. Reaching3 witnesses may stop alternative search with `searchComplete=false`; witnesses are not ranked best/top3. No silent atom truncation. Wall-clock cancellation/failure preserves an honest incomplete state and never an infeasibility claim; run in a bounded worker so the repository transaction/UI remain responsive. Do not persist a worker queue in the first slice.

At5 sources/12 items there may be5^12=244,140,625 leaves before pruning, so admission limits alone cannot promise completion. The approved six-item example has at most729 leaves per branch. Do not add an unfunded choice to every item: required scope stays fixed; show necessary monetary gaps or impossible items without optimizing partial scope. Compare only the explicitly selected branches, not an implied full outcome tree or expected-value forecast.

| Output state | Precise interpretation |
| --- | --- |
| Needs input | Missing/unconfirmed/stale applicable facts, terms or support completeness. Do not invoke unknown-as-zero/permissive defaults. |
| Feasible | At least one independently checked witness under this branch and encoded confirmed assumptions. Search may be incomplete; no optimality or scientific/legal certification. |
| Infeasible | Valid complete model with a direct complete proof or exhaustive admitted search proving no witness. Always scoped to encoded assumptions/branch. |
| Unknown | Work/cancellation limit without a witness/proof; preserve explored count and cause. Limit is not infeasibility. |
| Invalid model/witness | Bad shape, unsupported scope, duplicate identity, missing reference, dependency cycle or invalid candidate witness. A witness failure does not prove model infeasibility. |
| Failed execution | Worker/crash/internal validation/storage failure; no compatibility conclusion and no partial accepted allocation. Preserve manual inputs and allow explicit retry. |

Official alternatives: [CP-SAT](https://developers.google.com/optimization/cp/cp_solver) offers integer constraint solving and proof/status machinery; [MIP](https://developers.google.com/optimization/mip/mip_example) is credible for richer linear/split models. Both introduce runtime/package/adapter and explanation work absent from the current TypeScript app. Greedy independent ranking may miss feasible combinations and cannot certify infeasibility; it is unsuitable as the decision engine. The custom enumerator is chosen for a tiny auditable domain, not presumed faster or more capable than established solvers.
