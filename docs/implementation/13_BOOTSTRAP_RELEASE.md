## Public interface handoff

[Module README](../../modules/bootstrap/README.md) documents contracts, caller example, exact limits, states and commands. Public entrypoint: `modules/bootstrap/src/index.ts`.

- `validateInput` / `parsePlanningInput`: strict version-1 bounded synthetic planning model, exact retained quote/hash/range validation, closed graph/references, one project/attempt, mandatory confirmation and future-unstarted work, semantic set normalization.
- `planBootstrap`: at most 12 nodes/8 gaps/4,096 subsets; dependency and required-product closure, exclusion rules, unique shared node charging, upper/lower cash/time/effort/compute plus serial peak RAM/scratch capacity, known versus unresolved alternatives, funding branches, exact-gap-set partial frontier, honest minimum/proof statuses.
- `freezePlan` / `verifySnapshot` / JSON/Markdown helpers: copied normalized inputs, authoritative recomputation, separate canonical payload/envelope SHA256, deep frozen returned records, exact JSON roundtrip and escaped source text. These are pure values; no durable save is implied.
- `assessPlan`: separate current/stale/missing/unknown assessment using per-dependency manifests, explicit evaluation date/expiry, selected action owner/deadline and current source heads/file status. Global workspace revision is not a domain dependency. Historic quotes remain downloadable when current source files are unavailable.
- `lib/bootstrap/ports.ts`: a **feature-owned proposed read port** and explicit unavailable implementation; no invented task-03 export/DTO and no fixture fallback.

Limits are 80,000 UTF-8 input bytes and 256,000 frozen-export bytes. Frontiers display at most 8 entries with full count/truncation; excluded/unknown closure diagnostics display at most 32 with full count/truncation. Per-value input quantities max 1 billion; aggregates stay safe under the closed model and use separate safe-integer result bounds. Null quantities retain unknown status. No inference is made from expected favorable findings.

Future work only: started/sunk/completed nodes are rejected. One serial researcher/workstation lane is modeled. RAM/scratch are per-node peak reservations; callers must include already-retained outputs in each reservation. No parallel/retained-storage scheduling, real currency conversion or remaining-cost accounting is implemented.

## Parent P1 correction: consistent copied identities

Parent independent review of `97fa6dc` correctly identified that individually exact quotations could contradict each other across gaps: one source ID/version could carry different full text with independently recomputed valid hashes; one physical document-version ID could carry different byte hashes. Snapshot digest checks and authoritative solver recomputation alone did not detect that contradiction. This was a real missing boundary invariant, so the earlier core acceptance was reopened.

`model.validateInput` now checks all retained feedback, including optional gaps and repeated copies inside one gap, with separate consistency maps:

- `(sourceId, version)` → one full text/hash and immutable physical origin ID/hash, scoped to project/attempt. Quote ranges are deliberately excluded from this identity.
- `sourceId` → one current latest version/exclusion state and owner scope, including across historical versions.
- `documentVersionId` → one immutable byte hash/current integrity state and owner scope, including across different source IDs.
- Current action ID → one identical revision/kind/owner/deadline/state copy and owner scope, preserving legitimate shared actions while rejecting contradictory copies.

Distinct valid quote ranges over one source version, different historical source versions/origins under the same current source head, consistent file references across different sources, and distinct file-version IDs with identical bytes remain allowed. Conflicts throw before planning/freezing; `verifySnapshot` also rejects a contradictory payload even after an attacker recomputes both envelope/payload hashes. These checks establish internal copied-input consistency only; authoritative host/physical-byte validation remains gated.
