# Judge questions and credible answers

- What is technically distinctive? Point to the implemented algorithm/contract and visible behavior, not the count of SDKs or agents.
- What did you build during the event? Use SUBMISSION's contribution ledger; distinguish reusable kit code from new project work.
- Does it really use AI? Name the actual configured provider/model/path, or clearly state local algorithms and labeled fixtures. Do not equate all structured output with model inference.
- How do you know it works? Show representative cases, baseline, evaluation results and known failures. Small synthetic tests are sanity evidence, not population validation.
- What about privacy/security? Explain server-only credentials, relevant validation, ownership/RLS and retention actually implemented. Avoid blanket compliance claims.
- What breaks first? Name the recorded limitation, timeout/usage boundary and recovery.
- What would you do next? Prioritize one real-user validation or reliability improvement tied to evidence.

Owner supplies a concise answer and supporting file/log for each before rehearsal.
