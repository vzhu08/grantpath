## Verdict and value

Add a small NIH sample through the same anonymous Grants.gov search/detail provider as Task 09, with explicit authoritative-notice review. This offers useful biomedical breadth without a second provider, account, paid service or automated scraper. The useful mechanism is **public record → retained metadata version → authoritative passage → researcher decision → affected application**, rather than simply displaying more grants.

The most compelling proof is an observed disagreement: an NIH record marked posted with a future catalog closing date can have an application due date already in the past. Another verified NIH record has future cycles. A trustworthy discovery workflow distinguishes these cases instead of treating posted status, expiration or a single metadata date as permission to apply. Official details and the evidence ledger are in [source checks](real-grant-data/SOURCE_EVIDENCE.md).

Broader federal opportunities are technically accessible; exact subagency coverage, notice type and source-text interpretation make blanket coverage a poor hackathon cut. Public award history is accessible context, but does not supply successful proposals, scores, current opportunities or a researcher's award terms. Automatic complete eligibility/requirements extraction is not supported by the present labeled-line parser.

**Recommended later slice:** retain the NSF behavior and add up to three verified NIH records, manual refresh, metadata-only import and a bounded manual authoritative-text review. No NIH sponsor-ready proposal template, clinical-trial determination, submission or institutional certification follows. Demo is October 26, 2026; exact cutoff and duration are unknown. | Award history | Which topics/institutions were previously funded; what project periods and amounts were reported? | NIH RePORTER project/fiscal-year records or USAspending awards/transactions. ### Failure, stale and restart behavior

- Keep last-good content and original independent status/detail observation times through timeout, HTTP/schema/envelope error, oversize, missing fields and an empty result window. No successful time on failure, no fixture fallback. `404` means unavailable source record, not proven closure/deletion; search absence proves neither.
- Retry only bounded transient failures with backoff and bounded `Retry-After`; no automatic retry for malformed data/auth errors/unexpected redirects. [Official status guidance](https://www.grants.gov/api/status-codes) recommends backoff for 429; [version guidance](https://www.grants.gov/api/api-versioning) permits additional fields/values, which still need conservative validation.
- Preserve atomic reservation/latest-state commit and receipt replay before stale-revision rejection. A user save while networking must survive; late work cannot replace newer heads. On restart active reservations become interrupted; explicit retry gets a new attempt and does not duplicate imports or notices.
- Metadata-only change never advances human `lastCheckedAt`, call/source/application revisions, requirements, waivers, stages, template confirmation, drafts or frozen packets. Material notices are non-waivable review decisions; acknowledgment is not resolution. A→B→A remains observed history.
- An explicit authoritative shared-call review retains old sources/citations and invalidates affected applications through existing rules. Exact no-change decisions target compared versions; a new material version reopens review. Dirty editor buffers survive 409.
- Treat HTML and notice text as inert untrusted input. Do not execute scripts/remote instructions or use catalog links as arbitrary server fetch targets. Credentials remain absent; no researcher content leaves the machine. Unknown codes/unsupported text/size remain visible failure or uncertainty.
- Validate graph/hash/identity on reads and before writes. Preserve corrupt data with actionable failure; no reset to demo. Migration backup, reset retention, storage reserve and pruning policy must follow final 09 and main. Do not prune referenced source/catalog history or frozen packets.
